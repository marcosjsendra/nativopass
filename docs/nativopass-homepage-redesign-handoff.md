# NativoPass Homepage Redesign — Brand Discovery & Development Handoff

## 1. Project Overview

**Project:** NativoPass Homepage / App Home Redesign  
**Role:** UI/UX and Frontend Visual Prototype  
**Primary Goal:** Recreate the existing Figma homepage design locally, then iterate on it with new visual and UX directions before handing the approved design/code structure to the app developer.

NativoPass is a Costa Rican platform that connects **members** and **affiliated businesses**:

- Members receive discounts, benefits, rewards, and access to offers.
- Businesses receive exposure, traffic, customer acquisition, and promotional opportunities.
- The app acts as a hub where both sides benefit from participating in the ecosystem.

A comparable business model is **Yuplón**, although NativoPass should be positioned as more than a coupon/deals platform.

# 3. Brand Discovery

## Core Product Idea

NativoPass should not be presented merely as:

> "An app with discounts."

The stronger positioning is:

> **A lifestyle membership ecosystem that makes everyday activities more rewarding.**

The product connects everyday experiences such as:

- Restaurants
- Cafés
- Shopping
- Hotels
- Wellness
- Fitness
- Beauty
- Services
- Entertainment
- Experiences
- Local businesses

with member benefits such as:

- Discounts
- Promotions
- Exclusive offers
- QR-based benefit redemption
- Rewards
- Points
- Prizes
- Member-only opportunities

The emotional value is therefore not simply **saving money**.

The broader value is:

> **Doing the things you already enjoy, but getting more value from them through NativoPass.**

# 4. Brand Positioning

NativoPass should visually feel like a combination of:

- Lifestyle platform
- Local discovery platform
- Membership program
- Rewards ecosystem
- Benefit network
- Costa Rican business community

It should **not** feel primarily like:

- A generic coupon website
- A fintech product
- A QR scanner
- A collection of abstract 3D gift boxes
- A discount card with no emotional identity

The product is fundamentally **human and local**.

People use NativoPass while:

- Eating
- Shopping
- Traveling
- Relaxing
- Exercising
- Going out
- Discovering new places
- Using local services

The UI should therefore combine:

> **Real-world lifestyle + NativoPass digital layer**

# 5. Core Communication Strategy

The homepage should answer three questions very quickly:

## WHY?

Why should I use NativoPass?

Example message:

> **Disfrutá más. Pagá menos.**

---

## HOW?

How do I receive the benefit?

Example message:

> **Escaneá. Ahorrá. Disfrutá.**

---

## WHERE?

Where can I use NativoPass?

Example message:

> **Siempre hay algo Nativo cerca de vos.**

This creates a simple homepage narrative:

> **WHY → HOW → WHERE**

This is stronger than leading with product mechanics such as QR scanning.

# 12. Development Goal

Create a local frontend prototype that:

1. Recreates the current Figma homepage.
2. Serves as the visual baseline.
3. Allows rapid UI experimentation.
4. Allows side-by-side design iterations.
5. Can be published online for client review.
6. Provides readable frontend code for the production developer.
7. Focuses entirely on visual/UI behavior rather than production backend logic.

This prototype is effectively:

> **A coded interactive design system / high-fidelity frontend prototype.**

It is not intended to become the production application unless the production developer later chooses to reuse parts of it.

---

# 13. Recommended Technical Approach

Because the production application's technology stack is currently unknown, portability is important.

Recommended stack:

- **Vite**
- **React**
- **Plain CSS or SCSS**
- Semantic HTML
- Lightweight JavaScript only where interaction is required

Recommended approach:

> React components + normal CSS classes

Avoid making the prototype unnecessarily dependent on framework-specific styling systems.

For example, avoid heavily coupling the design to:

- Tailwind-only utility structures
- Proprietary component libraries
- Complex state-management libraries
- Backend frameworks
- Production authentication
- Database services

The final developer should be able to inspect a component and easily translate it into:

```html
<section class="hero">
    ...
</section>
```

and corresponding CSS.

---

# 14. Why Vite + React

React is useful here because the homepage may contain:

- Hero carousel
- Reusable business cards
- Category cards
- Offer cards
- Navigation
- Tabs
- Modal states
- Interactive prototype behaviors
- Repeated UI components

Vite keeps the environment lightweight.

However, the implementation should remain visually focused and portable.

# 15. Responsive Preview Requirement

A special requirement exists for the Netlify version.

## Desktop / Laptop

When the prototype is viewed on a desktop-sized screen:

The NativoPass interface should appear **inside a realistic or simplified mobile phone frame**.

Example structure:

```text
Browser viewport

        ┌────────────────────────────┐
        │        Phone Frame         │
        │                            │
        │   NativoPass Homepage      │
        │                            │
        │                            │
        └────────────────────────────┘
```

The phone frame acts as a presentation device so the client sees the design in the intended mobile context.

The actual interactive app prototype lives inside the phone viewport.

---

## Mobile Device

When the Netlify page is opened on a phone:

**Do not show the decorative phone frame.**

The NativoPass interface should use the full viewport naturally.

Conceptually:

```css
@media (max-width: 768px) {
    .device-frame {
        border: none;
        border-radius: 0;
        box-shadow: none;
        width: 100%;
        min-height: 100vh;
    }
}
```

Desktop:

```text
Presentation Mode
→ Phone mockup
→ App inside phone
```

Mobile:

```text
App Mode
→ Full-screen interface
→ No phone mockup
```

---

# 16. Phone Frame Guidelines

The desktop phone frame should remain secondary to the UI.

Prefer:

- Neutral frame
- Thin bezel
- Rounded corners
- Subtle shadow
- Realistic mobile aspect ratio
- Centered presentation
- Enough surrounding whitespace

Avoid:

- Heavy 3D phone renders
- Large reflections
- Decorative backgrounds that distract from the UI
- Device controls that interfere with interaction

The prototype itself should remain fully clickable and scrollable.

# 27. Interaction Philosophy

This prototype should be interactive enough to communicate the intended user experience.

Possible interactions:

- Hero slider
- Horizontal card scrolling
- Category selection
- Offer card hover/tap
- Bottom navigation
- Simple modal
- QR interaction simulation
- Rewards confirmation animation

Avoid implementing unnecessary production logic.

For example:

Do not build:

- Real authentication
- Real payment systems
- Real QR validation
- Production APIs
- Real rewards database
- Business management backend

Use mock data where necessary.

# 29. First Development Objective

The first coding session should **not begin by redesigning the homepage**.

The correct first objective is:

> Recreate the existing Figma homepage locally.

Once the baseline is stable:

1. Commit it.
2. Deploy it.
3. Preserve it.
4. Begin redesign iterations.

# 30. Initial Definition of Done

The baseline recreation is ready when:

- The homepage visually resembles the current Figma design.
- Main visual assets are local.
- Mobile scrolling works.
- Main interactions work or are reasonably simulated.
- Desktop shows the app inside the phone frame.
- Mobile removes the phone frame.
- Layout is responsive.
- Repository is clean.
- Netlify deploy works.
- The original baseline can be restored easily.

Only then should major visual exploration begin.
